# v0.96.0 — seven places the phone and the farm disagreed about a word

Wave 1 of `fafo_ios/SERVER_CHANGES.md`. Seven items, and they have almost
nothing in common as features.

What they have in common is the shape of the failure. In every one of them the
iOS app and this server disagreed about a name, a value or a shape — and the
disagreement was invisible from either side alone. The app's tests passed. This
app's ten thousand tests passed. The break coach on the shift screen said
"Break schedule unavailable" for months.

---

## The one idea

A contract between two codebases is only tested where something crosses it.

```
  iOS says                    server hears              what shipped
  ─────────────────────────────────────────────────────────────────────
  {"company": "…"}      →     resolve_company(dict)  →  HTTP 500
  joined_at 17:01:04    →     < 17:01:04.560880      →  "before the shift began"
  break_kind "Water"    →     not in the Select      →  break never filed
  farm_shift: "SHIFT-…" →     dropped by bind()      →  "farm_shift is required"
  phase: "before"       →     no such column         →  written into a filename
  get_task              →     32 fields, no template →  SOP unreachable
  a photograph          →     no file argument       →  kept on the handset
```

Each row is a boundary nobody stood on. So the tests added with this release —
`tests_standalone/test_wave1_mobile_gaps.py`, forty-two of them — are written
against the ARGUMENT the phone sends rather than against each tool's own
vocabulary. A test that called `resolve_company("Orchard Meadow, LLC")` directly
would have passed on every single day `get_break_policy` was returning 500.

---

## 13. `get_break_policy` answered HTTP 500 for every call

The endpoint read `resolve_company(args, actor)`. That is not the signature
`args.resolve_company` has — it takes `(company, required)` — so the args dict
arrived where a docname belongs, `(company or "").strip()` met a dict, and the
call raised `AttributeError` before it reached a query.

The only bodies that survived were the ones that named nothing at all, because
an empty dict is falsy. Every real call from a handset carries a company.

The company is now resolved and **not filtered on**, which is deliberate rather
than left over: `Labor Break Policy` has no company column, because a policy is
a state's rule — OAR 437-004-1131 is Oregon's whoever employs you. Resolving it
still earns its place: a body naming a company this site does not have is told
so by name. It comes back in the answer, so the read is not silently about a
different farm.

## 8. The crew-leader scan, refused on sub-second rounding

> TIMOTHY POLEHN is recorded as joining at 2026-08-18 17:01:04, before the shift
> started at 2026-08-18 17:01:04.560880.

The same second. Every ordering check on a shift compared two timestamps as
**strings**, which is right for two values of the same width and wrong the moment
the widths differ: `"…17:01:04"` is a prefix of `"…17:01:04.560880"` and
therefore sorts before it. The handset formats every timestamp it sends as
`yyyy-MM-dd HH:mm:ss`; Frappe stores microseconds. The two are never the same
width.

`shifts.to_the_second` truncates both sides. Truncation rather than a tolerance
window, because every one of these guards exists to catch a transposition — a
departure typed as an arrival, a date a day out — which is hours or days wrong,
never fractions of a second. A window is a number somebody has to defend; a
shared resolution is just two clocks agreeing on what a second is.

**Four more comparisons had the same defect** and are fixed with it: the close's
own "it would have finished before it began", the crew member who "left after the
close", `cancel_shift`'s start check, and the controller's end-before-start. Two
of those are live refusals on the same screen.

The guards still refuse what they were written for. An hour-early join and a
six-hour-early close are asserted as still refused, on purpose — otherwise this
reads as "the rule was deleted", which is a different change with the same green
suite.

## 9. `break_kind` had no value for water or shade

> Break recorded locally — break_kind must be one of Paid Rest, Unpaid Meal,
> Cool-Down. Got 'Water'.

"Recorded locally" means the break never reached the farm. Under OAR
437-004-1131 and WAC 296-307-097 the break log **is** the evidence that heat
relief was provided — the record an inspector asks for after a heat event — and
it was silently failing to be created for exactly the two kinds those rules are
about.

Both event types have been on `Farm Shift Compliance Event` since it shipped, and
`CARE_EVENTS` has counted them per worker since v0.64.0. What was missing was the
payroll classification that lets `log_shift_break` reach them.

**Three records, one clock.** Water, shade and cool-down are separately *required*
provisions — an inspector asks whether SHADE was provided, not whether a
cool-down was — so the timeline keeps them apart, and the shift summary now
counts `water_break_logged` and `shade_break_logged` beside the existing
`cool_down_logged`, which still means Cool-Down alone. But the cool-down *cycle*
they satisfy is one clock (`breaks.HEAT_RELIEF_KINDS`): a crew just out of the
shade must not be told a cool-down is overdue.

## 1. The close-out, refused on a parameter name

`routes.bind` reduces a request body to the keys the method **declares**. An
undeclared `farm_shift` was dropped before any guard saw it, so the close came
back saying the argument was required while it sat in the body — the same shape
as the `assign_housing` renames of §18.

`farm_shift` is the spelling the dispatch surface already uses (`assign_farm_task`
and `create_farm_task` have taken both since v0.72.0) and the column the Farm Task
and the Attendance row actually carry, which is why a client that learnt the word
there sent it here too.

Resolved through the existing `_one_spelling`, so two spellings disagreeing is
refused rather than guessed at. Attendance for a whole crew is written off this
call.

## 6. `phase` on task evidence — before and after, as data

The phase travelled in the filename — `FT-…_photo_before_….jpg` — which an
auditor can read and nothing can query. The app would not send an unrecognised
fifth key, and it was right not to: a strict validator refusing the whole
completion would lose the photographs, and a completion is the one submission on
this surface a worker cannot redo. The cabin has been cleaned; the crew has gone
home.

**Unset stays legal and is the ordinary case.** The key is emitted only when a
caller sends one, so the row is byte for byte what it was for every existing
caller and for the other child tables `normalise_evidence` feeds.

Lower case — `before` / `after` — because the handset ships `EvidencePhase` as a
Swift `String` enum with those raw values, so they round-trip with no translation
table on either end. A title-cased spelling is accepted on the way in, the mirror
of the tolerance `kind` already gets.

The mobile normaliser **drops** an unrecognised phase rather than raising, which
is the posture it already takes for an unknown `kind`: losing a label is
recoverable from the filename and losing the photographs is not. The strict
refusal is still there on the MCP tool.

The completion signature hashes file references and nothing else, so a phase
cannot change it — a completion queued offline before this release still replays
against it. That is asserted, because if it ever stops being true every phone
with an unsent completion files it twice.

## 7. A task could not reach its own SOP

`get_task` answered with thirty-two fields and none of them named the template.
The doctype has stored it since v0.41.0 and `dispatch._describe_task` has
reported it just as long — `shape.task` rebuilds its payload key by key and
dropped both it and the checklist on the way to the handset.

Not cosmetic: a worker holding a task had no way to reach the template's SOP, its
checklist or its `instructions`, because nothing in the answer said which
template to ask for. Fixing the attachment allow-list alone would not have helped
— the app could have read a template's attachments and still not known which
template to read.

Reported only where there is one, the rule `_describe_task` already follows.

## 10. A discipline record took no evidence

`create_discipline_record` accepted five fields and no file token, so a foreman
photographing the thing a warning is about had nowhere to send the photograph.
The record carried a sentence describing it instead, and that sentence is what a
dispute then turns on.

**The allow-list alone would not have worked**, which is worth recording because
it is the obvious-looking fix. `attach_file_to_document` on the mobile surface
runs `files._require_parent_write`, which asks Frappe for `write` on the parent —
and `Farm Incident Record` grants create/write to System Manager and HR Manager
and to nobody else. Adding it to that route's list would have published a door
that then refused every Foreman who walked through it, and reporting an incident
has been the field role's since v0.94.0.

So the evidence rides the create, on one gate. `inspections.normalise_evidence`
does the checking, unforked: a token pointing at nothing is refused there before
the record is written, and the forty-entry cap is its. The files are attached
privately — `is_private` through the File document, because flipping it *moves*
the bytes and rewrites the URL.

Anything that could not be filed comes back in `warnings` rather than raising: the
incident is the thing being preserved, and an attachment that did not stick can
be sent again while an unwritten warning cannot. A file already attached elsewhere
is reported rather than moved, so evidence is never taken off the record it was
filed against.

`Farm Incident Record` joins `ATTACHMENT_PARENTS` as **HR-gated**, so the
photographs can be read back by the accounts entitled to them. Reporting an
incident is the field role's; reading somebody's disciplinary file is not — the
line `get_discipline_record` already draws.

## Migrating

`bench migrate`. Three doctype JSONs change and all three changes are additive:

| DocType | Change |
|---|---|
| `Farm Shift Compliance Event` | `break_kind` gains `Water Break`, `Shade Break` |
| `Farm Task Evidence` | new `phase` Select — blank, `before`, `after` |
| — | no columns removed, no values rewritten |

No patch is needed and none ships. Nothing already stored changes meaning:
`cool_down_logged` still counts `Cool-Down` alone, an evidence row with no phase
is an evidence row with no phase, and every task without a template still reports
neither `template` nor `checklist`.

**No new tools and no new switches**, so no `allow_*` value is stranded — the
lesson of v0.95.0 does not apply here. `create_incident_record` gains an argument;
`end_shift` on the mobile surface gains an argument spelling.

## Verifying it

`python3 -m unittest discover -s tests_standalone -t .` — 10,763 tests.

The forty-two new ones are in `tests_standalone/test_wave1_mobile_gaps.py`, and
each fix carries its negative control, so green means the bug is gone rather than
that the guard was removed. Run against the tree as it was before this release,
32 of the 42 fail; the 10 that pass on both are exactly those controls.

The live half is outstanding and belongs to a deploy: `bench migrate`, restart
the `farmops` sidecar, then `POST farmops/api/mobile/get_break_policy` with a
company in the body and read a policy back instead of a 500.
