# v0.18.3 — evidence upload permission fix

**The one bug that kept every iOS completion stuck at "Saved on this device."**

Tim's iPhone testing after v0.18.2 hit the wall the release notes couldn't see
from the outside: tasks moved from Claimed → In-Progress → tapped Complete
→ green "Completed" banner on-device → but the server never saw the completion,
no Housing Inspection was ever produced, and the task stayed In-Progress. The
"will sync when you're back in range" text was iOS's offline queue reporting
that the sync was still being retried and still being refused.

## Root cause

`stage_file_chunk` — the first server call in the evidence pipeline — was
returning HTTP 403 to every Farm Ops user. Frappe's default PermissionError,
message "That request could not be completed."

Traced through `farmops_api` → `api/files.py` (guard passes: Farm Manager role
OK, Mobile Access Grant OK, kill switch OK) → `tools/uploads.py` → the actual
insert into the `Staged File Upload Session` doctype:

```python
return frappe.get_doc({...}).insert()   # no ignore_permissions
```

`Staged File Upload Session` and `Staged File Chunk` doctypes grant Desk
permissions to `System Manager` and `Accounts Manager` **only** — they exist
to keep operators out of the Desk list of half-uploaded photos. Farm Manager
(and Foreman, Farm Worker, Field Worker) never got permission to insert one.
So every farmops evidence upload failed at the first chunk, iOS queued the
whole completion for retry, and the retry kept failing forever.

`guard.endpoint` had already validated the caller as a Farm Ops role with an
active Mobile Access Grant — that IS the permission boundary for evidence
uploads. Frappe's doctype-level permissions are for Desk browsing, not for
this transport. Reused, they mean "no one can upload evidence unless they
have System Manager", which is nonsense for field workers on their phones.

## Fix

`tools/uploads.py` — every insert/save that writes to
`Staged File Upload Session` or `Staged File Chunk` gains
`ignore_permissions=True`, with a comment on the first one explaining why
(mobile upload guard already ran; Desk permission is a different question).

Four call sites patched:
- `_open_session` — creates a new session on first chunk
- `stage_file_chunk` — inserts each new chunk + saves session state
- `declare_expectations` — updates expected sha256 and size
- `commit_staged_file` (path where the whole file is re-staged as chunks) —
  bulk inserts + saves

No change to doctype JSON (Desk visibility stays exactly what it was — that's
correct; operators do not want the Desk showing every in-flight photo).
No change to guard, no new roles, no schema migration required.
