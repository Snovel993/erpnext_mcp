# v0.57.1 — the signature nobody could see, and the route nobody could reach

Two bugs and one gap, all found from one report: an I-9 Section 2 employer
signature, drawn on a handset over `I9-2026-0001`, answering
**"That task no longer exists — someone may have taken it."**

---

## 1. The route was never published. **This one needs an operator, not an upgrade.**

`submit_form_signature` was correct. Every test passed. The request never
arrived.

The funnel mounts paths with `tailscale funnel --set-path`, which is an **exact
mount point**, so the phone-facing surface is one line per method — and a route
added to `farmops_api/routes.py` is not published by having been added. Nobody
mounted the new ones. A probe of all 53 routes from outside the tailnet:

| Route | Added in | Reachable from a phone |
|---|---|---|
| `list_onboarding_reference_data` | v0.54.0 | no |
| `list_available_housing` | v0.54.0 | no |
| `assign_housing` | v0.54.0 | no |
| `collect_signature` | v0.55.0 | no |
| `dismiss_compliance_alert` | v0.57.0 | no |
| `submit_form_signature` | v0.57.0 | no |

47 of 53 published; the six above are every route added in the last three
releases. So the hiring wizard's Housing step, both signature routes and the
calendar's dismiss button have never worked in the field, on any handset, since
the day each shipped.

**Nothing on the server can see this happen.** The request stops at the proxy:
no access log line, no `MCP Action Log` row, no traceback. And what the worker
is shown is Tailscale's own plain-text `404 page not found`, which
`FrappeClient.serverMessage` cannot parse into a sentence — so the app falls
back to its generic miss for a 404, which is *"That task no longer exists —
someone may have taken it."* A foreman with a signature on the glass, told
somebody else took the job.

### What to run

On the Umbrel host:

```sh
sudo sh scripts/mount_farmops_funnel.sh          # --dry-run to see the commands first
```

New in this release, and **generated from the same list the route table is
asserted against**: `test_farmops_api.py` now checks the script and `routes.py`
against each other in both directions, so a route with no mount line fails the
suite. That assertion is the only thing that would have caught any of the three
releases above.

### And a way to ask

`validate_public_endpoint(probe_routes=true)` now POSTs an empty body,
unauthenticated, to every route from outside and reports which ones the funnel
is not carrying. **A 401 in JSON is the pass** — it proves the path reached
gunicorn and the credential gate refused an anonymous caller. A plain-text 404,
an HTML login page or a timeout means the path is not carrying and the method
behind it is unreachable no matter how correct it is.

## 2. The rendered federal forms never carried the signature. Since v0.51.0.

`i9_pdf.py` says at length that the capture is stamped into the page content and
the result flattened, so the retained copy cannot be edited back into an
unsigned one. That was true of `fill_i9_pdf` — which is where the stamping tests
point — and false of everything that called it.

`render_i9_pdf` built its record from `_i9_fields()`, which is documented as
"the fields returned by `get_i9_form`" and does not carry `section_1_signature`
or `section_2_signature`: those are the URLs of the ink, and a reader of the
record has no use for them. So `_signature_captures` looked for two keys that
were never in the dict and returned `{}` every time. No captures meant no
stamping **and no flattening**. `render_w4_pdf` had the identical bug against
`_w4_fields()` and `signature` — on a form whose own instructions say it is not
valid unless it is signed.

Both now read their capture columns explicitly at the render, rather than by
widening the two field lists, which would have fixed it by also putting private
file URLs into every `get_i9_form` and `get_w4` answer — a different decision,
made by accident.

**Two regression tests, at the level the gap was in.** The existing ones pass
`signatures=` straight to the pure renderer and prove the stamping; the new ones
go through `render_i9_pdf` and `render_w4_pdf` from a capture on the record. The
assertion is the surviving form-field count, because an unflattened page is the
tell and it needs no image decoding. Both use a **real PNG**: the renderer
deliberately swallows a capture it cannot read, so a fixture that merely looks
like a PNG takes the same silent path as the bug.

## 3. `submit_form_signature` hands the signed page back

The artefact the whole flow exists to produce, and the person who drew the
signature could not see it. `file_url` names a private File and the app
authenticates to the sidecar with `X-FarmOps-Token` rather than to Frappe, so
that URL is a login page to a handset — which is why `API_CONTRACT.md` §14.3 has
always said it is "recorded, not displayed".

So the page travels as base64 beside the URL, the way `get_employee_badge_pass`
sends a `.pkpass`, under a new `pdf` key (§14.3). With §2 above fixed, what comes
back is the page **with the ink on it**, flattened, carrying the electronic
signature record beside the image — who signed, when, from where, and 8 CFR
§ 274a.2. iOS decodes it into `SignatureAPI.SignedPDF` and the landed screen
grows a *"See the signed form"* button over a `PDFKit` view, with a share sheet;
the bytes never touch the filesystem.

Three things it is careful about:

* **It renders one where none existed**, which `collect_form_signature` will not
  do on its own — see `_redraw`, which argues that drawing a federal form nobody
  asked for is this app deciding something that is not its to decide. A caller
  passing `include_pdf` **has** asked, by name, in the same call. Default true on
  this route, because the pad is the caller; `include_pdf=false` for a client
  that only wants the write.
* **It is never fatal.** No `pypdf`, no template, a page that read back empty:
  `pdf.available: false` with the reason in `pdf.note`, and a signature that is
  on the record regardless. A page is worth less than the attestation it
  depicts.
* **A retry reads and does not draw.** The idempotent `already_signed` path
  hands back whatever page is on the record — rendering there would make the one
  branch that exists not to write, write.

## Upgrading

```sh
bench --site <site> migrate       # no schema change; the app version moves
sudo docker exec fafo-erpnext_server_1 supervisorctl restart farmops-api
sudo sh scripts/mount_farmops_funnel.sh
```

Then, from the Desk or an MCP client:

```
validate_public_endpoint(probe_routes=true)
```

`routes.unpublished` must be empty. It is the check this release exists for.
