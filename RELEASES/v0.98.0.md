# v0.98.0 — the screens the app already built, and the doors behind them

Wave 2 of `fafo_ios/SERVER_CHANGES.md` — items 2, 3, 5, 11, 12 and 14, the
"Core Mobile Surface". These are the features the handset has **already shipped
code for** and has been running on local fallbacks instead: a location picker
that offers one option, a note composer that saves to the phone, a countdown
computed from a statute compiled into Swift, and an SOP whose language is
guessed from its filename.

---

## The one idea

**Five of the six were transport gaps, not features.**

```
  what the app asked for        what the server had                   what happened
  ──────────────────────────────────────────────────────────────────────────────────
  create_field                  farm.create_field, since v0.12.0      404
  add_task_note                 add_task_note_via_mobile, v0.79.0     404
  create_dispute                report_direction="Worker Report",     404
                                and its four behaviours, v0.94.0
  list_attachments on a         a closed allow-list the template      refused by name
    Farm Task Template            was not on
  the task type Select          Farm Task.task_type, always           transcribed
                                                                        into Swift
```

The tool existed. The rules existed. The doctype existed. Nothing a phone could
reach reached them — which is why this diff is small for a wave this size, and
why the whole of `test_wave2_mobile_surface.py` is written against the **route
and the argument** rather than the tool. A test that called `farm.create_field`
directly would have passed on every single day that method was a 404 in an
orchard, which is the failure mode this file exists to make impossible.

## What shipped

### 11 — the four registers a task can be routed to

The largest item on the document, and it degraded every other feature: the
handset's "Where is it" picker showed only **"No location"**, so a shift's
location ended up as the typed note `Test 1` that no task could ever be routed
against. Ten spellings were probed on 2026-08-18 and all ten 404'd.

Six routes:

| route | who | what |
|---|---|---|
| `list_farm_locations` | anybody enrolled | Field + Irrigation Zone + Parcel + Housing Unit, one call |
| `create_farm_location` | Farm Manager | the polymorphic door, taking `doctype` |
| `create_field` | Farm Manager | ┐ |
| `create_irrigation_zone` | Farm Manager | │ the four names `LocationRegistryAPI` |
| `create_parcel` | Farm Manager | │ already prints in its own refusal |
| `create_housing_unit` | Farm Manager | ┘ |

**Five write routes and one write.** All five call `_create_one_location`, so
there is one gate, one argument map and one set of refusals — a rename cannot
open a fifth way in, and the four named doors are not four implementations to
keep in step. It is **not the dispatcher `routes.py` refuses**: nothing takes a
method name from a caller, and `doctype` is matched against a closed four-entry
table, exactly as `attach_file_to_document` matches its allow-list of parents.

**The read is open on enrolment and the writes are narrower than dispatch.**
`report_field_task` is open to every enrolled worker and *takes a location*, so
a picker gated on the dispatch role would leave the one call a field worker
makes about a place unable to name one.

### The role §11 asked for is Farm Manager

`LocationRegistryAPI.ownerRoles` is `{Farm Owner, Property Owner, Farm Manager,
System Manager}`, transcribed as a guess with *"tell us the real role and we
will match it"* written next to it.

- **`Farm Owner` and `Property Owner` do not exist.** `roles.ROLE_SPECS` creates
  seven roles and neither is among them.
- **`Farm Manager` is the answer.** `roles.py` grants it `FULL` on `GROUND`
  (Parcel, Field, Irrigation Zone) and on `CAMP` (Housing Unit) — read, write
  and create on all four registers.
- **`System Manager` is deliberately absent** and its absence costs nothing. It
  cannot reach this surface at all: `FARM_OPS_ROLES` does not list it and the
  enrolment gate refuses an operator's own account. `test_farmops_api` already
  asserts that Administrator holds every role on the site and still cannot call
  any of this. Listing it would advertise a permission seven gates upstream have
  already refused.

`guard.LOCATION_ROLES` is therefore a **strict subset of `DISPATCH_ROLES`** —
the only gate on this surface narrower than dispatch. A dispatched task is
undone by rejecting it. A register entry is routed through by every task, every
spray record and every acre of cost allocation this farm will ever file, and a
duplicate "Block 7" created at a tailgate is a second block the reports will
never merge. The refusal names the alternative, because the answer to "I cannot
add this block" is not *give me the role* — it is *the office adds it and you
pick it from the list five minutes later*.

### The one place the four registers genuinely disagree

The handset collects a uniform sheet — `{name, company, parcel, acres}` — for
all four. They are not uniform:

```
  Field            named field_name    hangs off a Parcel     takes acreage
  Irrigation Zone  named zone_name     hangs off a FIELD      refuses acreage
  Parcel           named parcel_name   hangs off nothing      takes acreage
  Housing Unit     named unit_name     hangs off a Parcel     has no acreage
```

A zone waters a **block**, not a whole title — so `parcel` on a zone create gets
a sentence explaining the difference rather than "field is required" about an
argument the caller never heard of. A parcel usually holds several blocks and
picking one would put a zone on ground it does not water.

And a zone's **acres become square feet on the way in**.
`create_irrigation_zone` refuses `area_acres` by name, because the controller
computes it from `area_sq_ft` and two independently settable figures are two
figures that will disagree. So this converts rather than setting a second one.

### 12 — the note, and the grievance

**`add_task_note` was seven 404s.** The write has been mounted since v0.79.0,
and `Route` builds every path off the wrapper's own name — so the published path
was `/mobile/add_task_note_via_mobile`. The app asked for `add_task_note`, which
is the MCP tool's name and what any reader would predict, then tried
`add_narrative`, `append_note`, `create_task_note`, `add_note`,
`create_narrative_note` and `log_task_note`. `list_task_notes` **is** published
plainly, so a record's narrative could be read and never written: every field
note a foreman typed is still in `LocalNarrativeStore` on one phone, labelled
"on this phone only". The older spelling keeps its route.

Both vocabularies are declared, because `routes.bind` delivers only what a
signature names — a method declaring `narrative` at a caller sending `note` is
not a rename that half works. It is an empty note, written and stored, with
nothing in the answer saying the words went missing.

**`create_dispute` is thirty lines because the register already existed.**
`Farm Incident Record` was built to carry both directions and v0.94.0 added
`report_direction` with four behaviours hanging off it. None was reachable in
the app's vocabulary, so a worker's grievance was filed through
`create_discipline_record` at the lowest step with `DISPUTE RAISED BY …` typed
into the description — which produces a **warning**: a step on a progressive-
discipline chain, in the file of the person who complained.

A Worker Report carries no `discipline_type` (a warning level on somebody's own
report files it as a step against them), gets no `prior_record` and no
`step_number`, and — the one that matters — **is not refused after a
termination**. A worker disputing the termination itself is precisely the report
that must not come back *"there is no step after the end of employment"*, and
under the old spelling that is exactly what it came back as.

`discipline_type` is **absent from `create_dispute`'s signature**, so `bind`
cannot deliver one; the tool's own refusal is the second lock.

**One column, two vocabularies, not two columns.** The plan allowed either a
`direction` field or a `create_dispute`. A second Select saying the same thing
in different words is table sprawl and leaves two columns to disagree about one
record — so `direction` (`disciplinary` / `grievance`) is an accepted *spelling*
of `report_direction` and the stored value stays the doctype's, which keeps the
Desk, the chain query and every written report reading one vocabulary.

### 2 and 3 — the procedure a standing job carries

`Farm Task Template` joins `ATTACHMENT_PARENTS` as **`False`** — no HR gate. It
is the only parent on that list that is a *definition* rather than an event, and
it is not a fact about a person: it is what this farm does when it cleans a
cabin, and the picker standing in front of the cabin is who it was written for.

Two Attach columns, `sop_document_en` and `sop_document_es`, because **the
language is a column and not a filename**. The app read it off `..._es.pdf` /
`..._spanish.pdf`, which works while the office follows a convention and fails
*silently* when they do not — a document it cannot place is offered with no
language badge, so a Spanish-speaking picker gets an unlabelled button and has
to open it to find out. A declared field also makes "there is no Spanish version
of this procedure" a gap somebody can see and close.

**They are deliberately not snapshotted onto the task**, which is the one
interesting decision here. Everything a task copies off its template is frozen
at creation — right for a checklist and an evidence contract, because nobody's
obligations should tighten under them mid-job. It is exactly wrong for a
procedure: an SOP corrected at the office has to reach the work already on the
board. So a task reads it **through** the `template` link v0.96.0 added, and
`shape.task` carries the two straight down so a phone at a cabin door does not
spend a second round trip on a tethered connection.

### 5 — the facts a task was carrying as prose

The taxonomy is now **read off this site's own meta** at
`get_current_user_context` — the call the app already makes at login — rather
than transcribed into `FarmTaskType.all`. A site that customises the Select,
which needs no release on this side, gets its own options immediately instead of
a picker missing them until the app ships again. Task types, urgencies, dispatch
modes, break kinds, both incident vocabularies, and the four location registers.

**One new column in the whole wave.** `affected_asset` is `asset`;
`affected_block` fills the `location_doctype`/`location` pair; `reported_by` is
`reported_by`. Only `observed_at` needed its own, and the reason is a rate
limit:

> `reported_at` is the filing stamp, and `dispatch._field_report_count` counts
> the five-per-hour anti-spam limit on it. A caller who could set it backwards
> could file a hundred reports dated an hour ago and the rule would count none
> of them.

So one is caller-settable and the other never is. There is a test that fails if
a future edit folds the two together. It goes in through
`datetimes.as_mariadb_datetime`, because the sender is an iPhone writing
`2026-08-18T07:12:00Z` and a Frappe Datetime column answers that with
`Incorrect datetime value` — the same wall the whole bucket capture queue hit in
v0.59.1.

`reported_by` is accepted on `create_farm_task` and **refused on
`report_field_task`**: there the reporter *is* the caller, and a body that could
name anybody else would put a stranger's name on a report they never made.

`estimated_duration_minutes` reaches `report_field_task` at last, so an ad-hoc
task stops sorting last on a board that orders by what work costs.

### 14 — the countdown every phone reads the same

`get_break_schedule(shift)` returns **instants, not durations**. That is the
whole item. `BreakSchedule` computes its countdown from the shift's start
against the farm's policy when `get_break_policy` answers and against the state
statutory minimum when it does not — honest, printed under the bar every time,
and *not synchronised*: seven phones in an orchard each work out their own
instants from their own idea of when the shift began, and they disagree by
whatever the clocks and the last sync disagree by.

Breaks are placed at **the middle of each equal work period**, which is the
placement OAR 839-020-0050(1) and WAC 296-126-092 both describe rather than a
spacing somebody chose:

```
  06:00 start, 8-hour shift, OR policy (2 rests + 1 meal)

  06:00 ─────── 08:00 ─────── 10:00 ─────── 12:00 ─────── 14:00
                 rest          meal          rest
                 10 min        30 min        10 min
                 paid          unpaid        paid
```

The `break_type` each row carries is `log_shift_break`'s own vocabulary, because
a countdown ends with a foreman tapping the button and what that button posts is
`log_shift_break(break_kind=…)`. A fifth set of words would have made the
handset carry a translation table between what it counted down to and what it
then had to log.

**The policy is read off the shift first and the state second, and the answer
says which.** A `Farm Shift` carries `break_policy`, stamped when the shift
started, and a policy amended in October must not retroactively change what
August's crew was owed. Shifts started before v0.58.0 carry no stamp, and an app
that cannot tell "this is your farm's policy" from "this is the state's default"
cannot print the sentence `BreakSchedule` prints.

The bands are keyed on **how long the shift is, not how long it has been**. Six
hours owes a meal period and four does not, so computing against elapsed time
would make the meal *appear* on the schedule four hours in — three hours after
the crew needed to know it was coming, and already overdue the moment it landed.
An open shift is assumed to run eight hours (`PLANNED_SHIFT_HOURS`, overridable);
a closed one is measured end to end and never guessed at.

## Two bugs, both already shipped, both silent

### `shifts.FIELDS` never carried `break_policy`

Three readers built their row from that tuple and then asked it for exactly that
key — `_break_summary`, `_compute_shift_production` and
`get_shift_crew_timeline`. The lookup returned `None` on **every shift ever
written**: the break reconciliation was skipped, and `get_shift_crew_timeline`
reported `"break_policy": null` for shifts that named one.

Nothing failed. A block of entitlement figures was simply absent, which is the
quietest way for a compliance number to go missing. `work_state` joins it,
because the schedule's state fallback has to read the state off the *shift*
rather than off the request — a phone that could name the state could ask for
California's rules on an Oregon crew.

### `require_scoped_doc` reads `company`; these four registers say `owning_entity`

Found by writing the test, not by reading the code. The new location writes
scope-checked their parent through `guard.require_scoped_doc`, which looks up a
column called `company`. All four of Field, Irrigation Zone, Parcel and Housing
Unit call theirs `owning_entity` — so the lookup returned `None`, the
`if company and …` guard was skipped, and **a Farm Manager on one entity could
have filed a block under another entity's parcel**: a permanent, unmergeable row
in somebody else's register.

`_scoped_location` is the hand-made check that reads the right column, and it is
the same trap `_attachment_parent` already documents for `Housing Unit`. It
answers **not found** rather than refused, so a caller cannot map another
entity's docnames by watching which error comes back.

## What did not ship

- **No MCP tool was added.** No `allow_*` switch, no registry entry, no
  catalogue count moved. Wave 2 is a mobile-transport release.
- **`set_field_boundary`, `set_zone_boundary`, `set_parcel_boundary`,
  `convey_parcel`, `link_parcel_to_asset`** and the three `update_*` tools have
  no route. Drawing a boundary, moving a title and repointing an asset are desk
  acts with a document open.
- **`title_holder`, `appraised_value`, `appraiser`, `appraisal_document`** are
  absent from `create_parcel`'s signature, so `bind` drops them. What a piece of
  ground is worth and who holds the deed both reach a financial statement.
- **`or_housing_law_compliant` and the detector dates** are absent from
  `create_housing_unit`. Those are what an inspection *finds*, and a route that
  let them be asserted at creation would let a cabin be registered as already
  compliant by whoever registered it.
