# v0.19.7 — a green board

**Released 2026-08-03. No behaviour changes. Twenty-one missing SPDX headers,
sixty-four ruff findings and a hundred and thirty-eight unformatted files —
all of it cleared, so CI says something again.**

Nothing in this release changes what the app does. Every tool behaves exactly as
it did in v0.19.6, the tool surface is unchanged at **238** (106 read, 132
mutating), and the suite runs the same **3,984 tests**. This is the maintenance
pass that makes the next release legible.

---

## 1. Why a release for this

Two CI steps had been red since before v0.19.5 — the SPDX-header check and the
`ruff` job. Neither failure was ever about the change that triggered it.

A permanently red board is worse than no board. A contributor who opens a pull
request and sees two failing checks learns, in one push, that failing checks are
the normal state here; the next genuine failure arrives on a board that already
had two, and gets read as more of the same. The signal was gone, and the only
way to get it back is to make green mean green — once, deliberately, in a commit
that does nothing else.

That is why this is its own release rather than a tidy-up folded into the next
feature. **A formatting sweep touching 163 files inside a behavioural change is
a diff nobody can review.** Separated, each is readable: this one is mechanical
by construction, and the next one will be entirely about what it actually
changes.

## 2. SPDX headers — 21 files

The CI step walks `git ls-files '*.py' '*.js' '*.yml'` and asserts each file
carries `SPDX-License-Identifier: MIT` in its first three lines. Twenty-one
files failed it: every one an empty `doctype/*/__init__.py` package marker,
accumulated across the DocTypes added in v0.19.2 through v0.19.6 — the audit and
compliance set, the training set, the shift and heat-exposure set, the staged
upload pair and the weather pair.

Each now carries the header as its sole line. They remain package markers and
Python still imports the module inside each folder; `test_packaging.py` asserts
only that `__init__.py` **exists**, never that it is empty, so nothing about the
package layout moved.

Files missing the header: **21 → 0**.

## 3. ruff — 64 findings, 138 unformatted files

Measured at ruff 0.16.1, the version CI installs.

**Findings: 64 → 0. Unformatted: 138 → 0.**

Eighteen were fixed by `ruff check --fix` and the rest by hand or by an audited
`--unsafe-fixes` pass, reviewed a rule at a time. The substantive ones:

- **`RUF013` implicit-optional (14).** `user: str = None` became
  `user: str | None = None` across `permissions.py`, `api/guard.py`,
  `api/shape.py`, `tools/calendar.py` and `tools/mobile.py`. Annotation only —
  no runtime path touches these.
- **`RUF012` mutable-class-default (5).** Class-level constants in five test
  classes — the method allow-lists in `test_api_mobile.py` and
  `test_farmops_api.py`, the coverage map in `test_ios_contract.py`, the
  hand-written chart in `test_wire_defaults.py` — now annotated `ClassVar`,
  which is what they always were.
- **`RUF015` (4)** `[... for ...][0]` became `next(... for ...)`. On the passing
  path these are identical; on a failing one the test errors with
  `StopIteration` rather than `IndexError`, which is a test failure either way.
- **`RUF005` (5)** list and tuple concatenation became unpacking. In
  `alerts/rules.py` the now-redundant `tuple()` around the spread went with it.
- **`RUF046` (1)** `int(round(x))` in `tools/weather.py` lost its cast:
  `shifts.hours_between` returns a float, so `round()` already returns an `int`.
- **`B904` (1)** the JSON-parse re-raise in `test_api_mobile.py` gained
  `from None`, which is what it meant — the parser's own error case name is the
  message, not the underlying `ValueError`.
- Plus the mechanical set: unsorted imports, three stale `noqa` directives, an
  unused import, an f-string with no placeholders, two `TimeoutError` aliases,
  an unsorted `__all__` and `__slots__`, and one whitespace-only line.

### One rule family switched off, deliberately

`RUF001`/`RUF002`/`RUF003` flag non-ASCII characters that resemble ASCII ones.
All sixteen occurrences here are deliberate typography in prose an operator
reads: an EN DASH in a numeric or regulation range (`1–30`, `§112.21–.30`), a
MULTIPLICATION SIGN in a dimension or a count (`8.5×11`, `600 × 800 KB`), and a
MINUS SIGN in arithmetic worked out in a comment.

Rewriting them to hyphens and a lowercase `x` would make the text worse —
`8.5x11` is not what check stock is called and `§112.21-.30` is not how the
regulation is cited. Sixteen scattered `noqa` directives would be more noise
than the rules are worth. They are ignored in `pyproject.toml`, with the
reasoning written beside them so the next person does not have to rediscover it.

## 4. What was not done

**No behaviour changed, anywhere.** Every fix above is a type annotation, a
formatting choice, a lint directive or a mechanically equivalent expression.
Nothing altered a value, a branch or a payload. Had a finding required a real
change, it would have been left and flagged rather than fixed quietly in a
commit whose whole claim is that it is safe to skim.

There is no ruff **baseline** file, and none was added. CI asserts `ruff check`
returns zero, not that it matches a recorded number — so the target is literal
zero and drift shows up the moment it appears, which is the only version of this
check that stays true.
