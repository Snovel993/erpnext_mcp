# v0.78.0 — what the register knew, and could not say

Six features, one new doctype, three routes iOS was blocked on — and one of them
is the difference between a worker walking into a treated row and not.

---

## The gap

The asset register has been scannable since v0.25.0. Every valve turned, every
tractor checked out, every cabin winterised has been landing in `Asset State Log`
for a year, with a timestamp and a name on it.

**A worker scanning a tractor got back a name, a state and a menu.**

Everything else they needed existed. The hours it had run were derivable from the
log — except nothing recorded a meter reading, so they were not. Whether it was
due for service was a question the register had no columns to answer. What was
open against it, what compliance was late, whether the block it was parked in was
closed after this morning's spray: each of those was a separate call, and
assembling the picture took seven.

On a rural cell at the end of a row, nobody makes seven calls.

**And the one fact that could hurt somebody was not recorded at all.**

---

## The REI, and why the arithmetic was already right and the shape was wrong

`stock_bridge.spray_windows` has computed restricted-entry intervals since
v0.69.0. It reads `Item.rei_hours`, takes the longest interval in the tank, and
stamps `rei_expires_at` on the Farm Task the spray closed. That arithmetic is
correct and this release does not change a line of it.

The shape was wrong for the question anybody actually asks.

```
what the app could answer:   "when does task FT-0412's window expire"
what a worker asks at 6am:   "may I walk into block 7"
```

Four things stood between the two:

- **It is keyed on the task.** Answering for a block meant finding every task
  that ever touched it and reading the latest one's stamp — a scan of the task
  register, in the hands of somebody holding a phone at a gate.
- **A task names one location.** One tank goes out over four blocks in a
  morning. Four blocks are four restrictions.
- **A spray need not come off a task at all.** Somebody mixes a tank and drives,
  and the record of that is a state change on the sprayer.
- **Nothing closed.** `rei_expires_at` is a timestamp in the past for ever after.
  "What is restricted *right now*" cannot be asked of a column like that without
  reading every task ever completed.

### What shipped

One new doctype, `Spray REI`. **One block, one product, one moment.**

`record_spray_application` files the spray and opens the windows: one record per
block, all with the same product, start and expiry, because the blocks were
sprayed from one tank in one pass and they clear together. It ends the spray on
the machine's state machine and stamps each block's `last_spray_date`.

`get_active_rei` is then one indexed query. `list_active_reis` is the board a
foreman reads before sending anybody anywhere.

**The refusal is the feature.** A tank whose products have no `rei_hours`
creates **nothing**:

```
no restricted-entry interval could be computed for this tank: nothing in the mix
has rei_hours set on its Item. Set it on the product's own record, or pass
rei_hours here for a state or certifier interval that is longer than the label.
NOTHING WAS RECORDED, deliberately: a window of zero hours reads as 'this block
is clear', which is the one wrong answer that puts somebody in a treated row.
```

A window nobody can compute must never look like a window that has passed. That
is the first test in `test_spray_rei.py` and it is first on purpose.

**One sentence, everywhere:**

```
REI active — Warrior II — 3.4 hours remaining — do not enter without PPE.
Block Home-7 was sprayed at 2026-08-15 06:10:00; entry is permitted from
2026-08-15 18:10:00.
```

A scan of the block renders that string. A scan of a machine parked in it renders
that string. A task dispatched to it renders that string. A worker who reads one
wording at a gate and a different one on a work order has been given two rules.

**A dispatch to a restricted block is warned, not refused.** §170.607 permits
early entry for specific tasks with the label's PPE. A server refusing outright
would be inventing a rule stricter than the regulation, and training foremen to
route around this app.

**Closing is an act, not a comparison.** `status` could have been derived —
active is `expires_at > now` — and deriving it would make "every restriction on
this farm right now" a query no database can answer, because a filter on a
computed value is not a filter. So the column is real, `close_expired_reis`
maintains it hourly, **and every read in the module runs that sweep first**. A
bench whose scheduler is wedged still tells the truth at a gate. That
belt-and-braces is not tidiness; it is the one record where a stale answer keeps
a crew out of a block that cleared hours ago.

`cancel_spray_rei` withdraws a window recorded against the wrong block, with a
required reason. Cancelled rather than deleted — *why did this block show as
closed on Tuesday morning* has an answer, and a deleted row has none.

## Engine hours: the series, not the last number

`asset_actions._MENU` has carried a `log_hours` row marked NOT BUILT since
v0.77.0, and the note under it said exactly what building it would take:

> Nothing on the Asset Register holds a meter reading, so there is nowhere to put
> the number and nothing to compare it against. Building it means one Float
> column for the last reading plus a log row per entry — the reading is only
> useful as a SERIES (hours since last service, hours this season), and a single
> overwritten column would answer none of those questions.

That is what shipped. `Asset State Log.engine_hours` is **the record** — one
reading per metered event, in a table that is append-only by its own controller.
`Asset Register.current_hours` is **a cache** of the highest reading seen, and
nothing is computed from it. A wrong cache is cosmetic and the next reading
corrects it; a wrong row in the series is a warranty claim.

**The reading rides on a state change** rather than getting a call of its own:

```
log_asset_state_change(asset_name="MC-Tractor-01", action="check_out",
                       engine_hours=1240.5)
```

The moment somebody reads an hour meter is the moment they are sitting in the
machine. A separate "log hours" call is one more thing to remember at the end of
a fourteen-hour day.

**A meter only counts up.** A reading below the last on record is refused —
`1240` typed for `12400` is the common case, and accepted quietly it becomes
"this tractor ran negative hours this season", which nobody reads as a data
error. `allow_meter_reset=true` says the instrument was swapped, and the
discontinuity is written into the log row's notes. The refusal happens **before**
the state change: somebody who fat-fingered the meter meant to make one record,
not half of one.

**Hours per session need both ends.** A checkout nobody metered leaves the
session empty rather than inventing a length from the last reading of any kind —
which on a machine serviced in between would bill the workshop's test run to a
worker's afternoon. A machine still out is an **open** session with a start and
no length; nobody has read the meter since it left the yard.

## Maintenance: two intervals, either alone complete

`Asset Register` gained `service_interval_hours`, `service_interval_days`,
`last_service_date` and `last_service_hours`. A tractor is serviced on hours, a
fire extinguisher on the calendar, a pump on whichever comes first — so both are
optional, both are computed, both are reported, and `due_on` names the one that
bit. Telling somebody "due in 265 days" because the calendar was checked second
is how a schedule stops being believed.

**Unmeasured is not overdue.** An hours interval with no reading ever recorded
comes back not-due, with the reason. Reporting it as due would fill a dispatch
board with unverifiable work on the day an operator first sets an interval —
which is precisely when they are deciding whether to keep this switched on.

`trigger_maintenance_tasks` raises one Farm Task per due asset through
`create_farm_task`, so the work carries an evidence contract and lands on the
same board as everything else. **`dry_run` defaults to true**: this makes work
for other people, and a tool whose first accidental call fills a dispatch board is
one an operator switches off rather than tunes.

**It will not raise a second task** where one is already open against the asset —
through either the `asset` column or the location pair, and whether raised by hand
or by last night's sweep. A job that re-raised nightly would produce the exact
backlog that teaches a crew to ignore the board.

`record_service` closes one out. Without it, every machine is overdue from the
day it was registered, which is the state that trains people to ignore the alert.

Scheduled at 04:30, after the regulation feed and before anybody is at a
tailgate — the first job on this app's list that raises work for other people.

## Water: the link the tree could not carry

`get_water_usage_report` rolls valve runtime up by zone, block, week, month, day
or valve, with an optional block filter. The report a water-rights filing and a
cost allocation are both written from.

**The measurement is `get_irrigation_runtime`'s, reused.** The same code handles
the four hard cases v0.76.0 wrote it for — a run that started before the window,
one that ended after it, one still open, and a close written by the cascade when
somebody shut a main. Two reports of one window must not disagree about how long
a gate was open, and `test_water_usage.py` asserts the totals against the older
tool's on identical data.

**`Asset Register.irrigation_zone` is new**, and it is the one link out of the
asset tree — because the tree could not carry it. An asset's parent is another
asset, so a valve could name the zone-shaped *asset* above it and never the
`Irrigation Zone` record that holds the flow rate, the water right and the block.
v0.76.0 stated that gap in its own docstring and refused to guess at a match by
name; this closes it with a column instead.

**Gallons are per-valve and never guessed.** A valve with the column empty
contributes its **minutes** to every total and no gallons, and is named in
`unpriced_valves`:

```
3 valve(s) have no flow rate, so their minutes are counted and their gallons are
not. Link each to its zone with update_registered_asset(irrigation_zone=…) and
set flow_rate_gpm on that zone, or pass flow_rate_gpm here to price them all at
one rate.
```

A volume figure that quietly dropped them would be short by an unknown amount, in
a document filed with a water district.

**A run is billed whole to the period it started in.** A set opened Saturday
night that ran into Sunday is Saturday's irrigation. Splitting the minutes at
midnight is arithmetically tidier and produces a report nobody can reconcile
against the valve log, where the run is one row with one start.

`get_irrigation_runtime` is deliberately untouched. Its `flow_rate_gpm` and
`irrigation_zone` arguments mean exactly what they meant, because a report
somebody has been running all season must not change its answer on an upgrade.

## The scan, in one call

`scan_asset` and `universal_scan` both return the whole picture under `status`,
composed once in `tools/asset_status.py`. `get_asset_status_report` is the same
block for a caller who is **not** scanning — so it stamps no `last_scan_at`,
because nobody was standing there, and a register that recorded desk queries as
field scans would make that column mean nothing.

| Key | What it carries |
| --- | --- |
| `state` | Current state, the type's default, last scan |
| `maintenance` | Due on hours / days, by how much, next service date |
| `engine_hours` | Meter now, this season, since service, sessions |
| `runtime` | For a valve: minutes today, this week, this season, running now |
| `parent_valve` | The valve above, and whether it is shutting off the water |
| `open_tasks`, `compliance_alerts`, `recent_activity` | |
| `active_reis` | Restrictions on the ground this asset stands on |
| `applied_reis` | For a sprayer: what **it** closed |
| `warnings` | Ordered by what would hurt somebody first |
| `sections_unavailable` | Named, not silent |

`active_reis` and `applied_reis` are kept apart deliberately. A screen that
merged them would tell a worker they may not enter the tractor shed.

`parent_valve` is the piece a valve scan could not do without: closing a main
shuts everything below it, so a lateral reading `open` under a closed main is a
valve with no water in it — and the worker sent to find out why nothing is
running needs telling about the handle three hundred yards uphill.

**Sections degrade; the call does not fail.** A scan is the most
latency-sensitive call this app makes and it is made by somebody standing in the
sun. A section whose doctype has not migrated, or whose register will not answer,
comes back empty and is **named** in `sections_unavailable` — "no open tasks" and
"the task register would not answer" are different sentences, and only one of
them is a reason to call somebody.

`needs_attention` and `warnings` are hoisted to the top level of a scan, because
they are what a screen colours the whole card on. **The flat keys every shipped
handset already decodes — `state`, `open_tasks`, `action_menu` — are untouched.**
The status block lands under one key precisely so it cannot overwrite them.

## The three routes iOS was blocked on

`register_asset`, `generate_asset_qr` and `attach_file_to_document` are on
`/farmops/api/mobile/…`. The Swift screens were already built; the flow they
perform — photograph the plate, register the asset, print the tag, file the
photograph — stopped at step two with a 404, because the first two have been MCP
tools since v0.25.0 and a handset does not speak that transport.

**The argument spellings are the tools' own.** `routes.bind` reduces a request
body to the keys a signature declares, so a wrapper that renamed `name` to
`asset_name` would silently drop the tag ID off every registration. Where a tool
takes two spellings for one column — `parent_asset` and `location` — both are
declared, because the tool refuses them only when they *disagree*.

**`attach_file_to_document` is the one that is narrowed, and the narrowing is why
it is publishable at all.** The tool attaches to any document on the site; the
wrapper carries an allowlist of the registers a field device already writes into
and refuses everything else by name. Every entry on that list carries a `company`
column, and that is a requirement rather than a coincidence:
`guard.require_scoped_doc` reads exactly that column to decide reachability, so a
doctype without one would be scoped by nothing. `Asset State Log` is what that
rules out.

`Employee` is deliberately absent even though the hiring wizard files six
documents against one. `attach_onboarding_document` is that door and it checks
the HR role; a second door onto personnel evidence with one fewer gate is the
thing an allowlist exists to prevent.

`allow_cancelled` is **not declared on the signature at all**, so `bind` cannot
deliver it and the tool's own refusal of a cancelled parent stands whatever a
body says. A cancelled document is history; deciding to add to it anyway is a
desk decision with the record open.

## Migration

```bash
bench --site <site> migrate
```

Adds the `Spray REI` doctype, six columns to `Asset Register`
(`irrigation_zone`, the four service-schedule fields, `current_hours` and
`hours_updated_at`) and two to `Asset State Log` (`engine_hours`, `hours_used`).

Nothing is backfilled and nothing needs to be. Every asset comes out of the
migration with no service schedule — which is the correct answer for a register
of valves and cabins — and `check_maintenance_due` says so per asset rather than
reporting the whole farm as overdue. Set an interval on the machines that have
one; link the valves that have a zone.

Ten new tools. Six read (`get_asset_status_report`, `get_engine_hours_summary`,
`check_maintenance_due`, `get_water_usage_report`, `get_active_rei`,
`list_active_reis`) and four write (`record_service`,
`trigger_maintenance_tasks`, `record_spray_application`, `cancel_spray_rei`).

**The two REI reads default ON.** Every other read in this app does too, but the
reason is different here: a restricted-entry answer an operator has to switch on
is one a worker does not get at a gate. The writes default off, as every write in
this app does.

## The tests

126 new assertions across three modules.

`test_spray_rei.py` opens with the refusal rather than with the happy path,
because a zero-hour window is the single worst thing this feature can produce.
`test_engine_hours.py` asserts the cache can drift without corrupting a season,
and that a rejected reading leaves no half-record behind.
`test_water_usage.py` checks its totals against `get_irrigation_runtime`'s on
identical data, and asserts that the older tool still refuses to price what it
was never told the rate for.

Two assertions that were red on `main` before this release are green now:
`list_cost_centers`, `list_suppliers`, `list_expense_receipts` and
`update_expense_receipt` had routes and were on neither contract set, so
`test_api_mobile` and `test_ios_contract` were both failing. They are listed
where they belong.
