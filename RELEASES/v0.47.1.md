# v0.47.1 — the record was complete and there was no form

**Four releases collected the data. None of them produced the document.**

v0.27.0 built the I-9 as a structured record with an immutable audit trail.
v0.47.0 closed the last three federal gaps in it — Section 1's three identifiers,
Section 2's document-title check, receipts, and Supplement B as a child table. By
the end of that, an I-9 Form on this site held everything Form I-9 asks for.

What an operator could hand to an inspector was a Desk print of the doctype:
eighty-four fields, two to a row, in the order the JSON declares them,
`naming_series` and `pdf_col` among them. 8 U.S.C. §1324a(b)(3) does not ask for
the data behind Form I-9. It asks for Form I-9.

---

## The decision: fill the government's page, do not redraw it

v0.36.0 draws a W-2 and a 941 from scratch with reportlab, and `form_pdf_renderer.py`
argues at length that this is the only honest thing to do: the IRS's Copy A is
printed in a specific red ink its scanners drop out, no laser printer produces
it, so anything this app makes is a working copy and says so twice on every page.

**Form I-9 is the opposite case in every respect that matters.**

| | W-2 / 941 (v0.36.0) | Form I-9 (v0.47.1) |
|---|---|---|
| How the agency publishes it | scannable red-ink stock, or an electronic filing | a **plain-paper fillable PDF** |
| What a real employer completes | the official stock, or a portal | that exact PDF |
| Where it goes | filed with the IRS, ODR, OED, ESD | **nowhere** — retained by the employer |
| Therefore the honest output | a reproduction, stamped a working copy | **the form itself, filled in** |

So the app ships the USCIS document — OMB No. 1615-0047, Edition 01/20/25, four
pages, 133 named AcroForm fields, no XFA — at `erpnext_mcp/templates/i9_form.pdf`,
byte for byte, and `erpnext_mcp/i9_pdf.py` writes values into its own fields and
hands back a copy. **The file on disk is opened read-only and never edited.** Its
SHA-256 is asserted by the suite, so a template that was swapped, corrupted in
transit or re-saved by a PDF editor fails a test rather than producing a form
nobody can file. `templates/README.md` carries the provenance and the three-step
procedure for the next USCIS edition.

## Four boxes left blank, and why each one is a decision

### Both signature boxes

Three of the four signature fields on the form are ordinary `/Tx` text fields. A
name typed into one **renders as a signature** and is indistinguishable from one
on the printed page. It is not one: an electronic I-9 signature has to meet
8 CFR 274a.2(h)'s own requirements, and a string this app typed into a PDF meets
none of them.

What the app genuinely holds is a signature *capture* and a timestamp. Those go
into the Additional Information box as what they are —

> Section 1 attested electronically 04/01/2026 07:14 from 10.0.0.5 via the Farm
> Ops app; signature capture retained on the record.

— so an auditor reads a fact instead of a picture of one, and the boxes stay
empty for a pen.

### The SSN comb

`tools/i9.py` has said since v0.47.0 that the last four digits are what this app
reads, that `ssn_full` is a Frappe Password field in the encrypted `__Auth`
table, and that nothing reads it back — *"the day something needs to (an E-Verify
submission) it should say so at its own call site."*

A printed I-9 has an SSN box. This is that call site, and it says so: two gates,
both required. The caller passes `include_full_ssn`; the site has `store_full_ssn`
on. The read writes `full_ssn: true` into the audit row, so a page carrying
somebody's number is findable afterwards. `get_i9_form` still does not return it,
and `generate_i9_pdf` — the handset endpoint — **does not accept the argument at
all**, because printing a nine-digit number onto a page a phone could mail
anywhere needs a retention decision an operator makes at a desk.

Absent both gates the comb is empty, which is the page an employee has always
been handed to fill in by hand.

The last four alone are never written into it. The comb has nine cells and no way
to say which four these are; five blanks followed by `6789` reads as an SSN
beginning `0000` to anybody not looking closely.

### The DHS alternative-procedure tick

`CB_Alt` attests that the employer examined documents under the DHS alternative
(remote) procedure. Nothing in this app records whether they did. A tick nobody
chose is a false attestation on a federal form.

### Supplement B's new-name boxes

They are for a worker whose legal name **changed**. `I-9 Reverification` records
the reason `Name Change` and does not record the new name, so filling them with
the name already printed at the top of the page would assert something nobody
said.

## The one field USCIS put on two pages

`Document Title 1` is a **single AcroForm field with two widget annotations**:
one in Section 2's List A block on page 1, one in Supplement B's second
reverification row on page 4.

One field means one value. Fill either box and both change — a hire-day document
title silently overwritten by a reverification made two seasons later, or the
reverse, and the resulting page looks perfectly plausible either way. It is the
kind of defect that would be found by somebody reading a printed I-9 in an
inspection.

`_split_shared_title` promotes the page-4 widget into a field of its own **in the
generated copy**, before any value is written: it is given the name, the field
type and the attributes its parent was lending it, removed from that parent's
kids, and appended to the AcroForm's own field list. The template on disk keeps
USCIS's structure; the copy this app produces has one field more than the copy it
started from.

It is the only place this module edits the form's structure rather than its
values. Both halves are pinned by tests — the split *and the defect it works
around* — so a future edition that fixes the duplicate name fails loudly and the
surgery gets deleted rather than carried forever as a thing nobody remembers the
reason for.

## `attach_signed_i9` — the half that is the federal record

Everything on the I-9 Form record is the data that was collected. **The page two
people signed is the thing §1324a asks the employer to have kept**, and until now
there was nowhere to put it.

The loop: `render_i9_pdf` → print → two pens → photograph → `attach_signed_i9`.
`generated_pdf` is only the page it was printed from, and the doctype's own field
descriptions say so.

The photograph arrives through the **existing** evidence path — `stage_file_chunk`
then `finalize_staged_file`, 512 KB at a time, hashed at capture and verified on
assembly, resumable over a thin field link — and this call names the File and
attaches it. No bytes cross the endpoint. A base64 body would have been a second
upload path with its own size limit, its own hash check and its own way of
failing halfway up a hill.

**Made private on the way in, whatever it was.** A signed I-9 names a person,
their date of birth and their immigration status; a public URL for one is a data
breach nobody has to guess a password for.

A second signed copy is **refused** without `overwrite`. It is the one write on
this doctype that could not be undone from the record itself.

## Three routes, and the first is a read nobody had

Every I-9 call on the mobile surface writes and hands back the record it wrote.
`get_employee` reports a one-word status. So a foreman who opened the wizard on
somebody already verified could be told `Verified` — and nothing else. Which
documents were examined? By whom? Is a receipt still outstanding? All of it on
the server since v0.27.0, none of it reachable from a phone, and every one of
those is a question an audit asks first.

| Route | What it is |
|---|---|
| `/farmops/api/mobile/get_i9_form` | the whole record: documents, verifier, receipt, reverification history. SSN is the last four. |
| `/farmops/api/mobile/generate_i9_pdf` | fills the federal form, attaches it, returns `file_url` to print from |
| `/farmops/api/mobile/upload_signed_i9` | files the photographed signed sheet against the record |

`get_i9_form` carries **the same one-record exception `get_employee` carries**: a
worker may read their own I-9 — their own immigration paperwork — and needs the
HR role for anybody else's. The caller is resolved through `Employee.user_id` and
never from the request body, so the exception cannot be claimed by naming
somebody. `upload_signed_i9` has **no** such exception: it writes the document
the employer will be inspected on, and an account that could file its own signed
I-9 could file one nobody signed.

## The Desk's Print button, and the two ways wkhtmltopdf fails

Frappe's Print button renders a Print Format through Jinja and then wkhtmltopdf.
With no format defined it renders the standard one — the field dump this release
opened with.

**The I-9 Print Format** is seeded on migrate: the record laid out as the form's
own sections, the citizenship attestation as ticked boxes, the three document
lists side by side in the columns they belong in, Supplement B as a table of
*every* reverification rather than the first three, and the retention dates. It
is a working copy and says so in a box at the top, because the thing it most
resembles is a federal form and the one thing it is not is one.

**Seeded, not fixtured**, and `standard = "No"`. `test_hooks.py` forbids the word
`fixtures` by name and `i9_documents.py` gives the reason: a fixture is rewritten
from the app's files on every `bench migrate`, so a margin an operator tuned for
their own printer would vanish at the next upgrade without a word. This creates
what is not there and touches nothing that is.

### Failure one: a broken `<img>`

wkhtmltopdf fetches every external URL synchronously with no timeout worth the
name. One image that 404s — a letterhead, a signature capture whose *private*
File URL the renderer cannot authenticate to — hangs the render or blanks the
page.

So the template references **nothing**: no `<img>`, no `<link>`, no webfont, no
logo, no `http` anywhere in it. Every rule and every tick box is a border or a
text glyph and the CSS is inline. It renders identically with the network
unplugged. The signature captures are reported rather than embedded — *"Signature
capture on file: yes"* — which is the fact rather than the picture, and is what an
auditor needs.

### Failure two: fontconfig

wkhtmltopdf asks fontconfig to build its font cache before it lays out a glyph.
fontconfig wants `/var/cache/fontconfig` writable; in the container it was either
absent or root-owned while the Frappe processes run as `frappe`. It then dies
with `Fontconfig error: No writable cache directories` and Frappe surfaces an
empty or failed PDF — which reads as a broken print format and is not one.

**No template can work around a renderer that cannot start**, so the fix is in
the image rather than in this app: `fafo-erpnext/build/Dockerfile` creates the
directory `0777` in a cheap layer at the bottom of the file, and `entrypoint.sh`
repeats it at every boot for the case a running container's `/var/cache` was
cleared. `0777` rather than `chown frappe` because the same cache is wanted by
whatever user each supervisord program runs as, and a directory only one of them
can write is the same outage for the others. Nothing secret is written there — it
is a font index.

## One new dependency

`pypdf` fills the form, and it is not a second reportlab: reportlab **draws** a
page this app laid out, pypdf **writes into** one somebody else published.

Imported defensively like `shapely`, `h3`, `segno` and `reportlab` before it. A
bench without it — or without the shipped template — loses exactly
`render_i9_pdf`, which says so by name with the pip command to fix it.
`attach_signed_i9` needs no PDF library, every I-9 value stays readable through
`get_i9_form`, and the Print Format still prints. Installing this app still
cannot break a site.

## What changed

**New tools (2):** `render_i9_pdf`, `attach_signed_i9`. 381 tools, 176 read, 205
mutating.

**New routes (3):** `get_i9_form`, `generate_i9_pdf`, `upload_signed_i9`.

**New files:** `erpnext_mcp/i9_pdf.py`, `erpnext_mcp/i9_print_format.py`,
`erpnext_mcp/templates/i9_form.pdf`, `erpnext_mcp/templates/README.md`.

**DocType changes:** `I-9 Form` gains `generated_pdf`, `generated_pdf_on`,
`signed_pdf`, `signed_pdf_on` and a `default_print_format`. `I-9 Audit Log` gains
the action `Signed Copy Filed`.

**Tests:** 5,895 standalone, up from 5,788 — `test_i9_pdf.py` (76) and
`test_i9_print_format.py` (24), plus seven mirrors in `test_ios_contract.py`.

**Outside this repo:** `fafo-umbrel-store/fafo-erpnext/build/Dockerfile` and
`entrypoint.sh` — the fontconfig cache directory. Those changes need an image
rebuild to take effect.

## Upgrading

```
bench --site <site> migrate
```

`bench migrate` adds the four columns, the audit-log action and the Print Format.
Nothing existing is rewritten and no I-9 changes. `render_i9_pdf` and
`attach_signed_i9` are mutating tools and are **off by default** — switch them on
in ERPNext MCP Settings.
