# v0.110.0 — the whole farm on one map, and a boundary you can walk

One new Desk page, one new server module, three new mobile routes, and five
lines exported from a file that already existed. No new MCP tools —
`registry.TOOLS` is unchanged and every count assertion in the suite stays where
it was.

---

## The two ideas

**A boundary nobody can look at is a boundary nobody checks — and until now
nobody could look at two of them at once.** This app has stored polygons since
v0.12.0 and drawn them since v0.32.0, always one record at a time, on the form of
that record. Open a Field, see that block. Open the next Field, see that block.

Which means the whole class of mistake that only exists BETWEEN records has never
once been visible: a block traced twice under two names, a zone drawn on the
neighbour's ground, two parcels overlapping by four acres, a cabin whose GPS was
typed with the longitude positive. Every one of those passes every validation
this app makes, is invisible on a form, and is obvious to anybody who sees the
farm drawn.

**And the phone could record a better boundary than the Desk could draw, with
nowhere to send it.** `routes.py` has said since v0.98.0 that the three boundary
tools were "DELIBERATELY ABSENT — drawing a boundary … is a desk act with a
document open". True of drawing one. Not true of walking one.

```
  before                                 after
  ────────────────────────────────       ────────────────────────────────
  one boundary per form                  /app/farm-overview
  no way to see two at once                every parcel, block and zone
  no way to see the farm                   every cabin, barn and shop
                                           one satellite map, one call

  phone: traces nothing, saves            phone: set_field_boundary
         nothing, 404 on all three               set_zone_boundary
                                                 set_parcel_boundary
                                                 — same tools, same checks
```

## The page

### What it is

`/app/farm-overview`. A standard Frappe Page in this app's module — the second
one it ships, after `/app/mobile-onboarding` — reachable by URL and from the
awesome bar. Three files on disk plus `erpnext_mcp/farm_overview.py`, which
publishes exactly one whitelisted method.

Three polygon layers, drawn largest first so a zone inside a block inside a
parcel is still clickable rather than buried under its own parent:

| Layer | Colour | Source |
| --- | --- | --- |
| Parcels | purple, dashed, faint | `list_parcels` + the one withheld column |
| Fields | green | `list_fields` |
| Irrigation zones | blue | `list_irrigation_zones` |
| Structures | orange pins | `list_housing_units`, `gps_latitude`/`gps_longitude` |

Every polygon and every pin carries a popup with the record's name, its detail
line, both acreages, and a link to the form.

### It reads, and there is no save path of any kind

Not an oversight and not a phase one. `api/gis.save_boundary` exists, it is the
one door a drawn boundary goes through, and it takes a doctype and a docname —
because what it does is compare a polygon against ONE record's recorded acreage
and refuse a disagreement past a quarter. **A map of forty blocks has no record
in front of it**, so a draw tool here would be a draw tool with nothing to check
the shape against.

The three forms that can be drawn on are still the three places a boundary is
set. This page links to them.

### Nothing about the map is copied

`geo_map_widget.js` has held the Leaflet CDN URL, both tile URLs, both
attributions and the zoom defaults since v0.32.0, and its own docstring says why:

> Seven copies of a Leaflet bootstrap is seven places for the CDN URL, the tile
> attribution and the zoom defaults to drift apart, and the first symptom of the
> drift is one form that mysteriously has no map.

This page is the eighth caller. v0.110.0 exports `load_leaflet`,
`add_base_layers`, `MAX_FIT_ZOOM` and `HOME_VIEW` on `erpnext_mcp.geo_map` —
**nothing was moved**, they are the same two functions the seven forms have used
all along — and a test asserts the page holds no tile URL, no CDN host and no
attribution string of its own. The Esri and OpenStreetMap attributions are the
condition of use for both providers rather than a courtesy, and a second copy is
a second place for one to be quietly dropped.

The widget is fetched by the page itself from `/assets/erpnext_mcp/js/`, because
`doctype_js` puts it on the seven forms that carry geometry and there is
deliberately no `app_include_js`. On any session that has opened a Field, it is
already loaded and the fetch does not happen.

### No shapely and no h3

`geo.parse` would have been the obvious way to read the stored text, and it calls
`geo.require()`. A bench without shapely loses the six geospatial TOOLS, which is
correct — those tools compute areas and containment. **Losing the ability to LOOK
at boundaries that are already stored would not be.** Nothing here computes
anything about the geometry beyond the smallest box that holds it, so it is
`json.loads` and a walk over the coordinates, in the standard library.

### Every number on it is a gap somebody can close

- **A row whose stored text will not parse is REPORTED**, with the docname, the
  reason and a link — not dropped. A boundary that silently does not draw looks
  exactly like a block that was never traced, and those are opposite problems
  with opposite fixes.
- **"Forty blocks" and "forty blocks, nine of them never traced" are different
  answers.** Both counts are on the legend. The first is a map that quietly lies
  about the size of the farm.
- **A structure with no GPS is a number, not a pin at `0, 0`.** Null island is a
  real place in the Gulf of Guinea and a map that flies there looks exactly like
  a map that works.
- **A coordinate off Earth does not decide where the map opens.** One vertex
  typed with an extra digit would otherwise stretch the frame across a continent
  and draw every real boundary as a dot. The shape is still drawn — it is the
  record, and the record is what somebody has to go and fix.
- **A register at the 500-row ceiling says so**, rather than a map that stops.

### The gate

`frappe.has_permission(<register>, "read")`, asked per register. **A register
this login may not read is NAMED and its layer is left off** — not a refusal of
the whole page. A farm where the office manager may read Fields and Parcels but
not the housing register gets the map with the buildings missing and a line
saying which layer was withheld.

The layer is ABSENT rather than empty, and the difference is the point: an entry
reading "Parcels — 0" would say the farm has no titles registered.

The entity picker is filtered by `frappe.has_permission("Company", "read",
doc=…)`, one check per Company, which is where a multi-entity farm's scoping
actually bites — all four registers hang off `owning_entity`. **The picker and
the scope are one list**, so an entity that is not offered is not reachable by
naming it in the request either.

What that does NOT do is stated in the module rather than discovered: the four
register tools read with `frappe.db.get_all`, which does not apply User
Permissions to the rows. The company filter is the gate doing the work.

### It degrades

No Leaflet — a bench with no outbound internet, a CDN that is down — and the page
prints the farm as a table of names, registers and centroids, every row linking
to its record. The same posture the widget takes for a single boundary, and the
argument is stronger here: a page that exists to show the whole farm has to say
what it knows about the whole farm even when it cannot draw it.

## The three mobile routes

### What changed, and the sentence it reverses

`POST /farmops/api/mobile/set_field_boundary`, `…/set_zone_boundary`,
`…/set_parcel_boundary`.

The line in `routes.py` was written when the only way to produce a boundary was a
mouse on satellite imagery. **A boundary recorded by carrying a phone round the
edge of a block is a ring of GPS fixes taken by somebody standing on the corner**,
rather than a guess at where the canopy ends in an image shot in another season.
An orchard block's corner IS a change in canopy, and the difference between where
the canopy looks like it ends and where the last row actually is comes to acres
over a farm.

That shape is what every geofence answer, every "was the crew in an authorised
area", every acre of cost allocation and every Worker Protection Standard answer
about which block was sprayed resolves through.

### Nothing is relaxed for the phone

All three call the same three tools the AI and the Desk map call, unchanged:

- the polygon is parsed and a self-intersection is refused,
- **the enclosed area is compared against the recorded acreage and a
  disagreement past a quarter is REFUSED outright**, with both figures named,
- containment against the shape above and below is reported and never enforced,
- every derived field — centroid, bounding box, H3 coverage, computed acres — is
  recomputed from the polygon rather than typed,
- `dry_run` goes straight through.

**The area check is what earns the route.** A walk that cut a corner, stopped
early, or was recorded with the phone in a pocket losing fixes produces a polygon
that is perfectly valid, is on Earth, and encloses noticeably less ground than
the block is recorded as. Nothing about the shape itself says so. A walk that
came out within a few percent is a walk that agrees with the deed.

`dry_run` is the argument a handset has the most obvious use for in the whole
app: the walk is finished, the operator is still standing in the block, and "what
would this shape do" before "do it" is the difference between a correction that
takes thirty seconds and one that takes a drive back out.

### The gate and the absent arguments

`guard.require_location_role` — **Farm Manager**, the same gate as the five
location creates and a strict subset of `DISPATCH_ROLES`. A register entry is
permanent in a way a task is not, and a boundary is the more consequential half
of it: a plausible-but-wrong shape passes every validation the tool makes.

`owning_entity` and `company` are **absent from all three signatures**, so
`routes.bind` drops them and no body can file a polygon against an entity the
account is not scoped to. The entity is read off the record the caller has
already proved they may reach — the same call `api/gis._save_boundary` makes for
the Desk.

The docname is scoped by `_scoped_location` and **not** by
`guard.require_scoped_doc`, which reads a column called `company` that none of
these three registers has — it would return None, skip its own check, and accept
a docname from another farm on the same bench. The refusal is NOT FOUND rather
than refused, so a caller cannot map another entity's docnames by watching which
error comes back.

Metered at `WRITE_LIMIT` (ten a minute), not `READ_LIMIT`.

### iOS

`MobileAPI.swift` names none of the three yet, so all three sit in
`PENDING_IOS_INTEGRATION`. The server half ships first and the iOS half is a
client change rather than a release of both — the order item 11's location routes
landed in.

## Upgrading

`bench --site <site> migrate` installs the Page record, and `bench build` is what
puts the exported widget on the asset path the page reads. A page that reports
"the map widget loaded but is an older build" is a build that has not run — that
case has its own sentence rather than looking like a network failure.

Nothing else is required. The three mobile routes are live on migrate and are
gated on Farm Manager; no switch turns them on, because `guard.endpoint`
deliberately does not consult the `allow_<tool>` switches — those are the AI's
leash, and an operator who distrusts the model must not thereby lose the ability
to record a walk.
