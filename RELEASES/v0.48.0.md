# v0.48.0 — a number with nowhere to go, a name nobody checked, and a form that was never printed

Three gaps in the federal employment forms, and they are three different kinds of
gap. One was a mapping that could not exist. One was a string the server believed
because a client sent it. One was a whole half of a form.

---

## 1. The EIN had nowhere to go, and that is the finding

`tools/i9._employer_block` has returned three keys since v0.47.1 — the employer's
legal name, their address, and `business_ein`, read off I-9 Settings or falling
back to `Company.tax_id`. `i9_pdf._section_2` wrote the first two onto the form
and never wrote the third. It reads like a line somebody forgot.

**It is not. Form I-9 has no EIN box.**

All 133 AcroForm fields in the shipped USCIS template (Edition 01/20/25) are
enumerated by the test suite, and Section 2's employer block is five of them: the
representative's name and title, their signature, today's date,
`Employers Business or Org Name` and `Employers Business or Org Address`. There
is no employer identification number field, because **the EIN is an E-Verify
datum** — it belongs to the E-Verify case, not to the retained form — and this
app keeps the two obligations separate.

So the number now goes where USCIS provides for an employer to write something
the boxes do not ask for: **Additional Information**, labelled, by
`_employer_lines`.

> `Employer EIN: 12-3456789.`

The alternative was to append it to `Employers Business or Org Address`, whose
own label is "Address, City or Town, State, ZIP Code" — a box that would then
hold something that is not an address, on a form an inspector reads box by box.
An unlabelled number in an address box is worse than no number at all.

`test_i9_pdf.TheShippedTemplate.test_form_i9_has_no_employer_identification_number_box`
pins the premise to the file rather than to this paragraph. If a later edition
grows an EIN box, that test fails and the right response is a field-table entry
plus deleting the prose line — not a bug report.

## 2. `verifier_name` was a string on a JSON body

Section 2 of Form I-9 is an attestation **under penalty of perjury** that a named
person examined the employee's documents. Until this release, that name was
whatever the caller typed — from a phone, in an orchard, with nothing on the
server that said whether that person had ever been authorised to make it. Form
W-4's Employers Only block had the same shape and the same gap.

### The roster

A new **Authorized Signer** child table on **I-9 Settings**. Six columns: the
User account, the printed name, a title, `can_sign_i9`, `can_sign_w4`, `active`.

It lives on I-9 Settings rather than in a Single of its own because it governs
both federal forms and a second Single holding six columns is table sprawl — the
same call this app makes everywhere about one place per fact.

### An empty roster authorises everybody, and that is the design

Every existing site migrates into an empty roster. A version that started
refusing signatures on migrate would break the I-9 flow on every farm running
this app until somebody found the new table.

**So the first row is the switch.** Adding one signer turns enforcement on for
the whole site, and `add_authorized_signer` says so in its own result and in its
summary line — because *"I added myself and now my foreman can't file an I-9"* is
the surprise this design has to pay for.

### Who signs is not who calls

The calling account is matched against `user`; the name written onto the form is
`full_name`. They are different facts and this app has always kept both — every
mutating I-9 tool writes an audit row naming the account regardless of whose name
went in the box. `_current_user` reads `security.caller_identity()` rather than
`frappe.session.user`, and that distinction is the whole feature: `mcp.handle`
becomes the MCP System User one line after it authenticates, so a roster matched
against the effective user would authorise every caller identically.

`submit_i9_section_2` and `submit_w4` now take the name and title **off the
roster row**, so `verifier_name` is optional where a roster exists. Passing one
still works — one authorised person filing for another is real (the foreman
examined the documents, the office files the form) — but the name has to be on
the roster too. A name nobody authorised is exactly the string this exists to
refuse.

### Nothing is ever deleted

`remove_authorized_signer` clears `active` and keeps the row. **There is no
delete tool and there will not be one.** A form signed last season was signed by
whoever was authorised last season, and a roster that forgets its own history
cannot answer the question a federal inspection asks. Deactivating the last
active signer leaves the roster *configured and empty*, which refuses every
caller — so the tool warns when a call does that.

| Tool | Default | |
|---|---|---|
| `list_authorized_signers` | **on** | The roster, plus `configured` — false means unrestricted |
| `add_authorized_signer` | off | Refuses a second row for one account |
| `update_authorized_signer` | off | `active=true` is the way back from a removal |
| `remove_authorized_signer` | off | Deactivates; warns when it leaves nobody |

All four are published to the phone as well, because a roster that can only be
edited in the Desk is one nobody fixes at 6am on a hire day. The account being
authorised is `signer_user`, not `user` — `guard.endpoint` injects the
authenticated caller into `user` and the route table drops any `user` a body
carries, so an argument by that name would have been dropped on the way in and
the endpoint would have silently authorised whoever called it.

## 3. The W-4 collected elections for four releases and never produced a form

The same gap `render_i9_pdf` closed for the I-9 in v0.47.1. v0.28.0 built the
W-4 as a structured record and the withholding engine has computed off it ever
since; what an employer could put in a folder was a Desk print of a doctype.

**And the form has a block the app had nothing for.** Step 5's *Employers Only*
row asks for the employer's name and address, the first date of employment, and
the EIN. All three were on the site and none was reachable from a W-4.

### The page

`erpnext_mcp/templates/w4_form.pdf` — the IRS's own fillable Form W-4 (2026),
shipped byte-for-byte. `erpnext_mcp/w4_pdf.py` is the field table, a pure
function with the same contract as `i9_pdf`.

**The employer block is resolved at render time, not stored.** The name, address
and EIN come from `i9._employer_block` — the *same* source Section 2 of the I-9
uses, so a farm that put `FAFO Farms LLC` in I-9 Settings does not put it
anywhere twice — and the first date of employment from `Employee.date_of_joining`.
A form rendered today carries today's registered address rather than whatever was
true when the employee filled the W-4 in.

What **is** stored is who processed it: `employer_signer_name`,
`employer_signer_title`, `employer_signed_at`, written by `submit_w4` off the
roster above.

**Step 1(a) is read off the employee's I-9 first.** The W-4 wants a street line
and a separate city/state/ZIP line; ERPNext's `Employee.current_address` is one
free-text blob, and splitting a blob into two boxes on a federal form is
guesswork. The structured address already exists on the I-9, collected in Section
1 by the same worker. The Employee record is the fallback.

### Four things it does not put on the page

| Left blank | Why |
|---|---|
| The signature and date | The IRS form has **no signature field at all** — Step 5's lines are printed rules. Unlike the I-9, there is nothing here to leave empty even by accident. |
| The SSN, Step 1(b) | A W-4 is completed by the **employee**. `render_i9_pdf`'s gated decryption exists because the employer verified that number; a second call site to fill a box the employee is holding a pen over would be risk for no gain. |
| The exempt tick | It claims exemption from withholding for a year under penalty of perjury, and nothing in the doctype records that claim. |
| Pages 3 and 4 | The worksheets. The IRS's own instruction is "keep the worksheet for your records" — the doctype stores the result, and the result is what goes on page 1. |

### The one structural edit: XFA comes out of the copy

The IRS file is a hybrid — an ordinary AcroForm plus an XML payload describing
the same form. **Acrobat renders the XFA and ignores the AcroForm.** A fill that
left it in place would produce a file holding every right answer and printing
blank in the reader an accountant is most likely to open it in. `fill_w4_pdf`
deletes `/XFA` from the copy; the template on disk keeps it, and that it still
has one is asserted too, so the year the IRS ships without it the deletion can go.

### The field names say nothing, so they are checked against geometry

USCIS named its I-9 fields after the boxes. The IRS named its W-4 fields
`f1_12[0]`. "Every name exists in the template" is not enough here — a *mistyped*
name would exist too, and would fill a perfectly valid field with the wrong
value on a federal form.

So `TheFieldTableIsCheckedAgainstGeometry` asserts where each name **sits**: the
two name boxes share a row, the filing-status ticks descend in the order the form
prints them, each tick declares the on-state the table gives it, Steps 3 and 4
descend in the order the form numbers them, and the three Employers Only boxes
are the bottom band left to right. It also asserts that the Step 5 signature band
holds no widget at all — the claim above, pinned to the file.

**Form W-4 is reissued every year**, which makes its checksum the most perishable
assertion in this app. A W-4 for a year the template does not print is still
rendered, and the result reports `template_tax_year_matches: false`. A prior
year's election on this year's page is a readable record; no form at all is not.

## Upgrading

`bench migrate`. Nothing changes behaviour on its own:

- The roster is empty, so I-9 and W-4 signing is unrestricted exactly as before.
  **Add the first signer when you are ready to enforce it, and add everybody who
  verifies documents — including yourself — in the same sitting.**
- `render_w4_pdf` and the three signer write tools ship **off**, like every
  mutating tool. `list_authorized_signers` ships on, like every read tool.
- Existing rendered I-9s are unaffected. Re-render one with `overwrite=true` to
  get the EIN line in Additional Information.
