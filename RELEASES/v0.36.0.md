# v0.36.0 — the numbers get a form to sit in

**v0.34.0 computed twenty boxes, fifteen lines and three state returns. It left
them in a JSON blob. This one draws the form around them.**

Two new MCP tools (331 total: 153 read, 178 mutating). No new DocTypes, no new
fields. One new pure module, `form_pdf_renderer.py`, on the same contract as
`form_generators.py`. One new declared dependency, imported defensively like the
three before it.

---

## What this release had to decide first

The obvious way to render a tax form is to recompute it and lay the result out.
That would have been wrong, and for the reason v0.34.0 already argued at length:
a payroll slip is a live record and a tax form is not. Hours get fixed, a rate
gets corrected, a shift nobody logged gets added three weeks late. If the page
recomputed, a W-2 printed in March would disagree with the W-2 printed in
February from the same record — silently, with the reader having no way to know
which one the SSA is holding.

**So the renderer reads `form_data_json` and computes nothing.** It is a pure
function of the stored values. The tool's only write is one attachment.

There is a test for exactly this: it renders a W-2, then adds nine thousand
dollars of payroll inside the tax year, then renders again, and asserts the page
still says four thousand.

```python
def test_rendering_changes_no_figure(self):
    name = self.a_w2()
    before = frappe.db.get_value("Tax Form", name, "form_data_json")
    self.seed_payroll("PAY-LATE", "2025-12-01", "2025-12-14",
                      [or_slip(employee="HR-EMP-00001", gross=9000.0)])
    self.tool_data("render_tax_form_pdf", {"name": name})
    self.assertEqual(frappe.db.get_value("Tax Form", name, "form_data_json"), before)
    self.assertNotIn("13,000.00", text_of(self.attached_pdf(name)))
```

## The second decision: what a page like this is allowed to look like

A page with `Form W-2` at the top, the SSA's own box numbering, and real wage
figures in the boxes is the single most mistakable artefact this app produces.
Somebody will print it. Somebody will mail it.

So there is no version of this page that does not say what it is:

* **A header note on every page** — `Generated by Farm Task Dispatch - verify
  before filing`.
* **A footer block on every page** naming the agency AND the channel the form is
  really filed through. Not a generic caveat: Copy A of a W-2 is red-ink
  scannable stock or an SSA filing through Business Services Online; a 1099-NEC's
  is IRIS or FIRE; 941 goes on the official form with deposits through EFTPS;
  OR-WR through Revenue Online, OQ through Frances Online, the ESD report through
  EAMS. A disclaimer that names where to actually go is one somebody reads.
* **Only the plain-paper copies are drawn.** W-2 Copy B, 1099-NEC Copy B. Copy A
  is ink no laser printer makes, and drawing it would be an invitation.

The disclaimer is drawn as the **last act of every page**, in `_finish_page`,
rather than by the code that starts one. That is why a forty-employee Washington
wage detail — which runs to two pages because the table overflows — has it on
page two as well. A reader who only ever sees the continuation page still gets
told. There is a test for that page specifically.

## The six layouts

| Form | Copy | What the page carries |
| --- | --- | --- |
| **W-2** | Copy B | Boxes a–f down the left, 1–14 in a ten-row grid on the right, 15–20 across the foot, one row per state |
| **1099-NEC** | Copy B | Payer and recipient blocks, boxes 1–4, boxes 5–7 per state |
| **941** | — | Employer block, the quarter ticked, Part 1 lines 1–15 with 5a–5d in both columns |
| **OR-WR** | — | The four quarters, the sum, the annual total, and the reconciliation against what was filed on each OQ |
| **OQ** | — | Per-month employee counts, then subject wages and tax for all four programmes |
| **WA-ESD** | — | Per-employee wage and hour detail, paginated, then the tax summary |

Letter size, portrait, Helvetica and Courier, in the real forms' box and line
numbering. Nothing here is scannable and nothing here claims to be.

## `warnings` is still the part to read first

Every generator returns a `warnings` list naming each figure it had to assume
rather than know — no year-to-date wages, no UI rate, a cross-state period with
no allocation. v0.34.0 made that the first thing a tool result shows.

The page reproduces it **verbatim and in full**, under *Before this form is
filed*, and a form with nothing to say says that too:

> The generator raised no notes on this form: every figure was computed from
> payroll records held in this system, with nothing assumed.

A page that dropped the warnings would look more certain than the arithmetic
behind it, which is the one way a working copy can do real damage.

## Two small things the layout gets right on purpose

**Labels wrap; values clip.** A label is prose and can take a second line. A
figure that took a second line would read as two figures, so a value too wide for
its box is truncated with a trailing dot instead — and a value that ran past its
own rule and over the next box's would look like it belonged to the column it had
spilled into. Both rules live in one place, `_Sheet.box`.

**Box 13's three ticks stack.** Side by side they do not fit the column, and the
third one lands on top of box 12b. A tick in the wrong box on a wage statement is
not a cosmetic problem.

## No compression, and why that is a testing decision

`reportlab` compresses content streams by default. This turns it off — the same
judgement `render/pdf.py` made in v0.10.0, for the same reason: these pages are a
few kilobytes, and an uncompressed stream is one a person can `grep` and `diff`.

It is also what makes the test suite mean something. A test can pull every string
off a page with one regular expression and no PDF parser, so *"box 1 says
4,000.00"* is a thing it can assert — rather than *"the renderer produced 9,506
bytes without raising"*, which is what a byte-count assertion actually proves.

## The tools

| Tool | Default | What it does |
| --- | --- | --- |
| `render_tax_form_pdf` | OFF | Draws one Tax Form's stored values and attaches the PDF to `generated_pdf` |
| `bulk_render_tax_form_pdfs` | OFF | The same for a set — every W-2 for a year, every 941 for a company |

**Three refusals worth naming.**

*A form that already has a PDF is refused* unless `overwrite` is passed. That
field may hold the copy somebody reviewed, or the one the agency issued, which
nothing here can reproduce. Overwriting repoints the field and **leaves the
earlier File attached** — the record gains and never loses, the same promise
v0.20.1's `regenerate_governance_document_pdf` makes.

*A form with no computed values is refused* rather than drawn. A page of zeroes
from an empty record is indistinguishable from a page of real zeroes.

*A bulk selection larger than `limit` is refused, not truncated*, and a bulk run
with no selector at all is refused outright. A batch that silently stopped short
would look like it had covered everything.

Inside a batch the opposite rule applies, because the failure mode is different:
one already-rendered form should not stop the other eighty-nine. So a form with a
PDF is **skipped and counted**, and one that fails to render is **recorded by
name with its reason** and the run continues. `rendered`, `skipped` and `failed`
between them account for every form matched.

## One new dependency, and it is optional at import time

`reportlab` draws the pages. The app's own `render/pdf.py` writes flowing text
documents — headings, paragraphs, tables — and would have needed a second layout
engine to place a grid of labelled boxes. This is the library whose whole job that
is, and these six layouts are the only thing in the app that needs it.

It joins `shapely`, `h3` and `segno` in being **imported defensively**. A bench
without it loses exactly two tools, which say so by name with the pip command to
fix it:

> this site is missing the reportlab Python package, which this app declares as a
> dependency — install it into the bench's environment with
> `./env/bin/pip install 'reportlab>=4.0'` and restart. The form's computed
> values are unaffected — read them with get_tax_form. Nothing was changed.

Every generator and every other tax form tool keeps working there. The numbers
are the deliverable; the page is a convenience. **CI runs the whole suite without
it first**, for the same reason it does for the geospatial pair — a run that only
ever saw the package present would never check the degrade path.

## For the operator

Nothing to migrate: no new DocTypes and no new fields. Make sure the package is
there —

```bash
./env/bin/pip install "reportlab>=4.0" && bench restart
```

— then tick what you want in **ERPNext MCP Settings → Tax Form Generators**. Both
new tools are off, as every mutating tool in this app ships off.

Render a form, open the PDF, and read the bottom of it before you read the top.
